# \[Ethereum\] ERC란 무엇인가? --- 이더리움 표준을 이해해보자

## 1. 들어가며

Ethereum과 Smart Contract를 공부하다 보면 `ERC-20`, `ERC-721`,
`ERC-1155`, `ERC-4626`, `ERC-4337` 같은 이름을 자주 접하게 된다.

처음에는 ERC를 단순히 "Ethereum에서 Token을 만드는 규칙" 정도로 생각하기
쉽다. 하지만 ERC는 Token에만 사용되는 개념이 아니다. Token, NFT, Smart
Contract Interface, Vault, Account Abstraction 등 Ethereum
Application들이 서로 호환될 수 있도록 만드는 다양한 표준과 규칙이 ERC에
포함된다.

## 2. ERC란 무엇인가?

ERC는 **Ethereum Request for Comments**를 의미하며 Ethereum 생태계의
Application Level 표준과 규칙을 다룬다.

대표적인 ERC-20은 Fungible Token이 공통으로 사용할 Interface를 정의한다.

``` solidity
totalSupply()
balanceOf()
transfer()
approve()
allowance()
transferFrom()
```

개발자들이 같은 Interface를 기준으로 Token을 구현하면 Wallet이나 DEX도
정해진 방식으로 Token과 상호작용할 수 있다.

## 3. EIP란 무엇인가?

EIP는 **Ethereum Improvement Proposal**의 약자로 Ethereum 개선 제안이다.

새로운 기능이나 표준을 추가하거나 기존 구조를 변경하려면 문제, 목적,
기술적 Specification, 보안 고려사항 등을 문서화해야 한다.

``` text
아이디어
  ↓
EIP 작성
  ↓
커뮤니티 논의 및 검토
  ↓
표준 또는 Network Upgrade 등에 반영
```

EIP 문서에서는 일반적으로 `Abstract`, `Motivation`, `Specification`,
`Rationale`, `Backwards Compatibility`, `Security Considerations` 등을
확인할 수 있다.

## 4. EIP와 ERC의 관계

EIP는 크게 Standards Track, Meta, Informational 등으로 나뉘며 Standards
Track은 다시 Core, Networking, Interface, ERC 등의 Category로 나뉜다.

``` text
EIP
├── Standards Track
│   ├── Core
│   ├── Networking
│   ├── Interface
│   └── ERC
├── Meta
└── Informational
```

따라서 ERC는 EIP와 완전히 별개의 체계가 아니라 **Standards Track EIP의
Application Level Category**라고 이해할 수 있다.

ERC-20은 EIP 번호 20번이면서 ERC Category에 속하기 때문에 EIP-20
문서이자 ERC-20 표준이다.

반면 EIP-1559처럼 Ethereum Protocol 자체의 Fee Market을 변경하는 제안은
Core 영역이므로 ERC-1559라고 부르지 않는다.

## 5. 왜 ERC가 필요할까?

표준이 없다면 개발자마다 Token 전송 함수를 다르게 만들 수 있다.

``` text
Token A → sendToken()
Token B → moveCoin()
Token C → sendAsset()
```

Wallet과 DEX는 Token마다 별도의 연동 코드를 만들어야 한다.

반대로 ERC-20을 따르면 다음과 같은 공통 Interface를 사용할 수 있다.

``` text
ERC-20
├── transfer()
├── approve()
├── transferFrom()
└── balanceOf()
```

이렇게 공통 규칙을 사용하면 Wallet, DEX, Lending Protocol, DeFi, NFT
Marketplace 등의 Application이 서로 쉽게 연결될 수 있다. 이것이 ERC의
중요한 가치인 **Interoperability**다.

## 6. ERC 번호의 의미

`ERC-20`, `ERC-721`, `ERC-1155`의 숫자는 버전을 의미하지 않는다.

ERC-721이 ERC-20보다 최신 버전이라는 뜻이 아니라 각각 다른 Proposal에
부여된 번호다.

## 7. 대표적인 ERC

### ERC-20

Fungible Token Standard다. 서로 대체 가능한 Token을 표현한다.

### ERC-721

Non-Fungible Token Standard다. 각각의 Token을 `tokenId`로 구분하여 NFT와
같은 고유 자산을 표현한다.

### ERC-1155

하나의 Smart Contract에서 여러 종류의 Token을 관리할 수 있는 Multi Token
Standard다.

### ERC-4626

Tokenized Vault Standard다. DeFi Vault의 Deposit, Withdraw, Share 등의
Interface를 표준화한다.

### ERC-4337

Account Abstraction을 다루며 Smart Account, UserOperation, Bundler,
EntryPoint, Paymaster 등을 이용해 Programmable Account 구조를 만든다.

## 8. ERC는 반드시 따라야 하는가?

개발자는 자신만의 Smart Contract Interface를 만들 수도 있다. 하지만 기존
Wallet이나 DEX가 ERC 표준을 기준으로 구현되어 있다면 Custom Interface는
별도의 지원 없이는 바로 호환되지 않을 수 있다.

따라서 ERC의 힘은 강제성보다는 **기존 Ethereum 생태계와의 호환성**에
있다.

## 9. ERC와 Smart Contract 보안

ERC 표준을 이해하면 Smart Contract를 분석할 때 정상 동작의 기준을 잡을
수 있다.

예를 들어 ERC-20을 분석한다면 `transfer`, `approve`, `transferFrom`,
`allowance`의 정상 관계를 알고 실제 구현과 비교할 수 있다.

하지만 ERC를 따른다고 해서 Contract가 자동으로 안전해지는 것은 아니다.
프로젝트가 추가한 Mint, Burn, Fee, Blacklist, Upgrade 등의 Custom
Logic에서 취약점이 발생할 수 있다.

## 10. 공부하면서 이해한 점

처음에는 ERC를 Token을 만들기 위한 규칙이라고 생각했다. 하지만 EIP
구조를 살펴보면서 ERC는 Ethereum Application Level의 다양한 표준을
다루며, 가장 중요한 목적 중 하나는 서로 다른 프로젝트가 같은 규칙으로
연결될 수 있도록 하는 것이라는 점을 이해했다.

ERC는 Ethereum 생태계에서 서로 다른 Application을 연결하는 **공통
언어**와 비슷한 역할을 한다고 생각한다.

## 11. 정리

  개념              의미
  ----------------- --------------------------------
  EIP               Ethereum Improvement Proposal
  Standards Track   Ethereum 표준과 관련된 EIP
  Core              Protocol 수준의 개선
  Networking        Network Protocol 관련
  Interface         Client API/RPC, ABI 등
  ERC               Application Level 표준 및 규칙
  Meta              Ethereum Process 관련
  Informational     정보 및 Guideline
  ERC 번호          Proposal에 부여된 번호
